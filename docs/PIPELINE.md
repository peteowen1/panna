# panna pipeline

_Generated by `ops/scripts/pipeline_guide.py` from `docs/pipeline.json`, using runs up to 25 Nov 2026, 3:01am (Sydney time). Do not edit by hand, except the notes section: rerun the generator._

How the football ratings and match predictions get built on GitHub Actions: two workflows, both started by the daily Opta scrape in the pannadata repo. The Predictions Pipeline builds the match predictions and the blog's game logs and publishes them; the Opta RAPM/SPM Pipeline refits the player ratings and publishes them. The pannadata repo's pipeline guide covers the scrape before these and the blog data build after them. Each workflow is timed on its own; runs are not stitched across repos.

## Predictions Pipeline

Workflow: [`predictions-pipeline.yml`](https://github.com/peteowen1/panna/blob/HEAD/.github/workflows/predictions-pipeline.yml). Median wall time **1 h 01 min** (range 47 min 17 s to 1 h 04 min), from the first job starting to the last job ending, over the 5 run(s) listed below.

Rebuilds the match statistics, refits the goals and outcome models, predicts every upcoming fixture, builds the blog's game logs, action equity and team strength files, then publishes everything to the predictions-latest and blog-latest releases. Only runs on the main branch that were started by the daily scrape or the weekly schedule are counted; manual and branch test runs are left out.

**What starts it, and what it starts:** The pannadata repo's daily Opta scrape sends opta-scrape-complete when it finishes; a weekly schedule (Wednesday 8am UTC) is the backstop. When it succeeds it sends predictions-complete to the pannadata repo, which starts the blog data build there.

## How to regenerate

```
python C:/dev/ops/scripts/pipeline_guide.py build --repo-dir <this repo>
```

It reads `docs/pipeline.json` (which workflows and jobs are the pipeline, one line per step) and the latest successful runs through `gh`, saves every response raw, and rewrites this file and `docs/pipeline-summary.json`. It fails if the config names a job, step or log pattern that no longer appears, so a renamed step cannot leave a stale description behind. Steps marked **(not confirmed)** were not checked against the script they run.
